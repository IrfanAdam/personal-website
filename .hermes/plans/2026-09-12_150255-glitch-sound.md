# Glitch sound — single voice for today

> **For Hermes:** implement phase-by-phase, verify each with `npm run lint:tokens` + `npm run build`; then `npm run ds:track`, `npm test`, and visual check on `/ds/#/changelog`.

**Goal:** Procedural glitch audio that marks exactly one thing — today on the changelog (later: the single primary CTA per page). One recognizable tick, proximity-loud, sparse timing, hard off, honest after reload.

**Architecture:** New `src/views/glitch-sound.js` (≤100 lines, WebAudio only — no files): one shared `AudioContext` + one shared noise buffer; exactly one tracked element per page; fixed-identity voice (timing random, timbre ~fixed); squared proximity gain; single clock with manual-trigger cooldown. Wiring in `src/views/init-sound.js` (toggle + auto-scan), sounds only where `data-glitch-sound` is present.

**Audit (grounded, 2026-09-12 — prior attempt, reverted):**
- 7 blobs × independent timers (1.5–4.8s) ≈ one burst every ~0.5s — constant chatter, not single glitches.
- 420px radius over blobs spaced ~1 blob-width apart: neighbours sound at ~0.8 while hovering today — proximity can't isolate; reads as "multiple sounds".
- Voice randomized bandpass 700–3900Hz + Q + decay + echo on every hit, plus a square-wave zip layer — no fixed identity; hiss one hit, whistle the next ("not clear").
- Hover tick + unlock-confirmation tick + scheduled tick could triple-fire on one gesture.
- Rule set from this audit: glitch (visual + audio) marks today only; other days stay silent/static.
