# ADAM/DS Maturity Implementation Plan

**Tags:** Design System, Component, Motion

> **For Hermes:** implement phase-by-phase in order. Each task is one focused change; verify with the stated command before ticking it off.

**Goal:** Turn ADAM/DS from style documentation into a cohesive, interactive design system that can build a landing page + portfolio from its own library.

**Architecture:** Token hygiene first (no visual change), then one reusable playground shell (`src/ds/playground.js`) that every primitive/component plugs into, then graduate motion literals to `--fx-*` tokens. Site files change only via token-alias swaps unless a restyle is explicitly approved.

**Tech Stack:** Vanilla JS + CSS, Vite 5, `tokens.css` single source, hash-routed `/ds` docs. Verify: `npm test` (= `lint:tokens` + `vite build`).

**Standing rules (every task):** ≤100 lines/file · `var(--token)` only outside `tokens.css` · `var()` invalid in `@media` (raw px breakpoints stay) · every radius via `var(--radius-*)` (= 0) · `prefers-reduced-motion` no-ops motion.

## Risks / tradeoffs

- **Taming the viewer changes brand feel** — mitigated by verdict gate (0.1) before any CSS moves; quarantine option keeps pixels 100% safe.
- **`tokens.css` 100-line ceiling** — one-line-per-group packing; DS-only tokens live in `ds.css`, never the canonical file.
- **`pill` → Button split** — `pill` keeps filter/tab role so existing consumers don't churn; Button is additive.
- **Scope creep (stats, testimonial, marquee)** — explicitly deferred; CTA is the only new marketing component.
