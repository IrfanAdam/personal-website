# Plan — ADAM/DS cleanup: close the last doc-code gaps

**Goal:** Remove dead DS chrome CSS, verify the Patterns accessibility section, and pin the card hover state into the Components docs as a forced-state specimen — with no visual regressions.

**Scope:** `src/ds/ds.css`, `src/ds/specimens.css`, `src/ds/specimens.js`, `src/ds/pages-patterns.js`, and `src/ds/pages-components.js`. Everything else in the design system is already green (`npm test` passes: lint:tokens + vite build).

## Current context / assumptions

- The design system is effectively finished and enforced by `npm test`. Tokens are canonical, all live sheets consume `var()` only, every sheet is ≤100 lines.
- The `/ds` docs site (served at `/ds` in dev via `vite.config.js` middleware and in prod via `vercel.json` redirects/rewrites) dogfoods real site classes, so specimens are pixel-true by construction.
- The dead CSS below is **not used by any route** — verified 2026-09-07 by grepping `src/` and `index.html`: zero JS/HTML references to `.ds-vp`, `.ds-vp-bar`, `.ds-anim`, `.ds-dotrace`, `.ds-media-bg`, `.ds-theme-row`. **Exception:** `.ds-ramp` IS live (`src/ds/specimens.js:31` renders it, `pages-foundations.js:13` calls it) — keep it. Likewise `.ds-spec` in `ds.css` is live (used by `pages-patterns.js` and `pages-components.js`) — keep it.
- The Patterns accessibility table already lists four real measured pairs (ink, muted, on-media, accent) matching its intro claim — Task 3 is a verification no-op, not a fix.
- The Components page describes hover/interactive states in prose (`scale(1.015)`, scrim swap, opacity 0.55) but a static doc page can't show a hover state. Whether that's a problem is a judgment call, not a bug.

## Architecture / proposed approach

Two independent, zero-risk slices, plus one verification and one deferred decision:

1. **Remove dead declarations** from `ds.css` (`.ds-vp*`, `.ds-anim*`, `.ds-dotrace*`) and `specimens.css` (`.ds-media-bg`, `.ds-theme-row*`), keeping the live `.ds-spec` and `.ds-ramp` rules. This is pure deletion — no code touches the removed classes. Verify with `npm test` (lint still green, build still succeeds, `/ds` still routes).
2. **Verify the Patterns accessibility section** — re-audit shows it already carries four real measured pairs; no change expected.
3. **Pin the card hover state in the Components docs.** Add a `.force-hover` forced-state specimen (mirroring `card.css:79-81`) so the hover swap is visible without hovering — no screenshots, no rot when tokens change.

No re-architecture, no new tokens, no new components. The DS is done; this is housekeeping.

**Step 1 — let `cardHTML` take an extra class.** In `src/ds/specimens.js`, change lines 20-23 from:

```js

export const cardHTML = (title, meta, img, tags = [], extraClass = '') => `
```

## Risks, tradeoffs, and open questions

- **Removing dead CSS is safe but irreversible in this commit.** If any route ever gets wired to `.ds-vp`/`.ds-anim`/`.ds-dotrace`, it'll need those rules back. The plan assumes they're genuinely unused (no JS references them today). If you want to be extra cautious, move them to a `src/ds/reserved.css` file instead of deleting — but that's clutter for dead code and the DS otherwise prunes aggressively.
- **Accessibility ratios are approximate by design** (the DS already says "~"). Don't polish them to two decimals — that implies a precision the system doesn't claim. If you add the two missing rows, keep the same "~" style.
- **Task 4's `.force-hover` duplicates three declarations from `card.css:79-81`.** If those hover rules change, the specimen must change in lockstep — the code comment in Step 2 flags the coupling. A screenshot would rot silently; this fails loudly and stays pixel-true because it reuses the same token-driven rules.
- **No token changes, no radius changes, no color changes.** This plan touches only docs CSS and one prose table. If `npm test` is green before, it should be green after — that's the guard rail.
